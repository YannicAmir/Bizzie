# Architecture Instructions

This document outlines the architectural standards and guidelines for the Bizzie Flutter application. All developers (Human or AI) must adhere to these rules to maintain a scalable, maintainable, and testable codebase.

## Architecture Overview

This app uses **Clean Architecture** combined with **Feature-Driven Architecture**. This ensures separation of concerns, independency of frameworks, and testability.

### Core Principles

1. **Separation of Concerns:** The code is divided into distinct layers (Data, Domain, Presentation) with specific responsibilities.
2. **Dependency Rule:** Source code dependencies only point inwards. Inner layers (Domain) know nothing about outer layers (Data, Presentation).
3. **Feature Autonomy:** Each feature is self-contained in `lib/features/[feature_name]`.
4. **Dependency Injection:** All classes are registered via `injectable` annotations — never register manually in `bootstrap.dart` or call `GetIt.I<T>()` from feature code.

## Folder Structure

The project follows a strict directory structure.

### Full Project Architecture Reference

```plaintext
lib/
├── app/
│   ├── l10n/              # Localization (BizzieLocalizations)
│   ├── navigation/        # Navigation helpers
│   ├── pages/             # Top-level page routing wrappers
│   ├── routes/            # GoRouter route definitions + AppRoutes constants
│   └── themes/            # AppTheme, AppColors, AppTextStyles, AppAssets
├── bootstrap/             # App entry point setup
│   └── bootstrap.dart
├── config/                # Firebase + environment config
├── core/                  # Shared cross-feature infrastructure
│   ├── analytics/         # Core analytics models
│   ├── constants/         # App-wide constants (e.g. FirestoreConstants)
│   ├── data/              # Shared data utilities (FirestoreService, TimestampConverter, cache)
│   ├── domain/            # Shared domain models and interfaces
│   ├── enums/             # Global enums
│   ├── error/             # Failure & Exception definitions
│   ├── interfaces/        # Core interfaces (IAnalyticsService, ILocalStorageService, etc.)
│   ├── logging/           # BizzieLogger wrapper
│   ├── network/           # Network info + interceptors
│   ├── services/          # Core platform service wrappers
│   └── usecase/           # Abstract UseCase base classes
├── di/                    # Dependency injection setup
│   ├── injection.dart     # GetIt + injectable configuration
│   ├── injection.config.dart  # Auto-generated by injectable
│   └── register_module.dart   # Manual @module registrations (Firebase, SharedPreferences, etc.)
├── env/                   # Envied-generated secrets
├── features/              # Modular Features (see feature structure below)
├── services/              # App-level service implementations
│   └── firestore_service.dart
└── shared/                # Global UI components, utils, constants
    ├── constants/
    ├── enums/
    ├── models/
    ├── utils/
    └── widgets/
```

### Feature Structure (`lib/features/[feature_name]/`)

Each feature follows this strict directory structure:

```plaintext
lib/features/[feature_name]/
├── data/
│   ├── dtos/              # Data Transfer Objects (@freezed + json_serializable)
│   │                      # Each DTO includes fromJson, toJson, fromDomain(), toDomain()
│   ├── datasources/       # Datasource implementations (remote + local)
│   └── interfaces/        # Datasource interfaces (IXxxRemoteDataSource, IXxxLocalDataSource)
│   └── repositories/      # Repository implementations (implements domain interface)
├── domain/
│   ├── enums/             # Feature-scoped enums
│   ├── extensions/        # Domain model extensions
│   ├── interfaces/        # Repository interfaces (IXxxRepository)
│   ├── models/            # Pure Dart domain models (@freezed)
│   ├── services/          # Domain services (pure logic, no I/O)
│   └── usecases/          # Single-responsibility use cases (implement UseCase<Result, Params>)
└── presentation/
    ├── analytics/         # Feature-scoped analytics tracker class (XxxTracker / XxxAnalytics)
    ├── bloc/              # BLoC: XxxBloc, XxxEvent (@freezed), XxxState (@freezed)
    ├── extensions/        # Presentation-layer extensions (e.g. state extensions)
    ├── models/            # Presentation-only view models (@freezed)
    ├── utils/             # Presentation utilities (formatters, helpers)
    ├── views/             # Screens / Pages
    └── widgets/           # Feature-scoped, reusable widgets
```

> **Note:** Not every feature requires every sub-directory. Only create directories that have content. Simple features (e.g. `settings`, `home`) may omit `data/` entirely and have no repositories.

### Core Structure (`lib/core/`)

Shared logic used across multiple features:

- `error/`: `Failure` (sealed via freezed union) and `Exception` definitions. All repository methods return `Either<Failure, T>`.
- `usecase/`: Abstract base classes — `UseCase<Result, Params>`, `StreamUseCase<Result, Params>`, `SynchronousUseCase<Result, Params>`, `NoParams`.
- `interfaces/`: Core service interfaces — `IAnalyticsService`, `ILocalStorageService`, `IConfigService`, etc.
- `data/datasources/`: Shared datasource infrastructure (e.g. `FirestoreService`).
- `logging/`: `BizzieLogger` — always use this, never raw `print()` or `debugPrint()`.

## Dependency Injection

This project uses `injectable` with `get_it`. **All classes are registered via annotations on the class itself:**

| Annotation | Use case |
|---|---|
| `@injectable` | Standard registration (new instance per injection) — used for BLoCs |
| `@lazySingleton` | Lazy singleton — used for analytics trackers and use cases |
| `@LazySingleton(as: IXxx)` | Lazy singleton registered against an interface — used for repositories and datasources |
| `@Injectable(as: IXxx)` | Per-injection instance registered against interface — used for datasources |

After adding or modifying any injectable class, run:
```
dart run build_runner build --delete-conflicting-outputs
```

## Boundaries & Rules

1. **Domain layer** must contain **only pure Dart code**. No Flutter dependencies, no Firebase SDK calls, no HTTP calls.
2. **Presentation** calls **UseCases only** — never repositories or datasources directly.
3. **Data layer** implements interfaces defined in the **Domain layer**.
4. **BLoCs** contain orchestration and state logic only — no HTTP calls, no JSON parsing, no storage reads/writes.
5. **Routes** must be defined in `lib/app/routes/app_routes.dart` and referenced via `AppRoutes` constants. Never hardcode route strings.
6. **Analytics** are handled by a feature-scoped tracker class in `presentation/analytics/` — injected into the BLoC. Never call `IAnalyticsService` directly from a widget.
7. **DI** uses `injectable` annotations — never register singletons manually. Never call `GetIt.I()` from feature code.
8. **Logging** always uses `BizzieLogger('ClassName')` — never raw `print()`.

## Shared Logic

- Shared domain models: `lib/core/domain/models/`
- Shared data utilities: `lib/core/data/`
- UI components: `lib/shared/widgets/`
- Form validators: `lib/shared/utils/validators.dart` — do not duplicate validation logic.

## Code Reviews

All code changes involving structural modifications must be reviewed against these architectural guidelines.
